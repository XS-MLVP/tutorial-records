# e203_ifu_litebpu 验证需求与计划

## 1. 验证目标

e203_ifu_litebpu 是 E203 IFU 中的轻量级分支预测单元，验证目标是通过输入输出端口确认其静态预测、目标地址操作数选择、JALR 数据相关等待、rs1=xn 寄存器读取状态管理以及复位时序行为满足设计文档要求。验证过程中不修改 DUT RTL，若测试失败且符合规格预期，应基于源码分析并记录为设计缺陷。

## 2. 待验证接口

输入接口包括 `clk`、`rst_n`、`pc`、`dec_jal`、`dec_jalr`、`dec_bxx`、`dec_bjp_imm`、`dec_jalr_rs1idx`、`oitf_empty`、`ir_empty`、`ir_rs1en`、`jalr_rs1idx_cam_irrdidx`、`dec_i_valid`、`ir_valid_clr`、`rf2bpu_x1`、`rf2bpu_rs1`。输出接口包括 `prdt_taken`、`prdt_pc_add_op1`、`prdt_pc_add_op2`、`bpu_wait`、`bpu2rf_rs1_ena`。

该模块包含时钟和低有效复位，验证必须使用 Step 接口推进时序，并在每个测试用例中明确初始化输入与复位状态。

## 3. 功能验证范围

### 3.1 静态预测功能

需要验证 JAL 总是预测跳转，JALR 总是预测跳转，Bxx 条件分支根据立即数符号进行静态预测：负偏移预测 taken，非负/正偏移预测 not taken。还需覆盖无分支指令时不应产生跳转预测。

### 3.2 目标地址操作数选择

需要验证 `prdt_pc_add_op1` 在 JAL/Bxx 时选择 `pc`，JALR 且 rs1=x0 时选择 0，JALR 且 rs1=x1 时选择 `rf2bpu_x1`，JALR 且 rs1=xn 时选择 `rf2bpu_rs1`。`prdt_pc_add_op2` 应为 `dec_bjp_imm` 的 PC 宽度低位。

### 3.3 JALR 数据相关与等待控制

需要验证 rs1=x1 时对 OITF 非空、IR 目的寄存器冲突等条件产生 `bpu_wait`，依赖解除后不等待并给出正确操作数。需要验证 rs1=xn 时对 OITF/IR 阶段相关条件的等待、IR 清除或 IR 不使用 rs1 时的依赖忽略，以及等待信号与读寄存器使能之间的互斥关系。

### 3.4 rs1=xn 读寄存器状态管理

需要验证 `bpu2rf_rs1_ena` 只在合法读请求周期拉高，避免同一条 JALR xn 指令重复读寄存器；读状态应能在后续周期清除；复位后状态应处于安全空闲状态。

### 3.5 时序与复位行为

需要验证低有效复位期间输出与内部读状态不会产生非法请求，复位释放后首个有效指令可正常预测。所有检查必须通过公开输入输出端口完成，非必要不观察内部信号。

## 4. 风险点与边界条件

主要风险点如下：

- 立即数符号位判断错误，导致 Bxx 前向/后向静态预测反向。
- `dec_bjp_imm` 到 `prdt_pc_add_op2` 的位宽截断错误，尤其是负数立即数低位保留和 PC 宽度边界。
- JAL/JALR/Bxx 多个解码信号同时有效时优先级或输出组合异常。
- JALR rs1=x1 的 OITF/IR 依赖判断过严或过松，造成不必要等待或漏等待。
- JALR rs1=xn 的 IR 清除、IR 不读 rs1、OITF 非空、IR 非空组合条件容易出现控制漏洞。
- `bpu2rf_rs1_ena` 与 rs1=xn 读状态机可能重复发起请求、无法清除，或复位后状态错误。
- `dec_i_valid` 为 0 时若仍产生等待、读请求或预测，可能造成流水线误控。
- `bpu_wait` 与预测/读寄存器控制信号的互斥约束可能被破坏。

## 5. 验证方法计划

### 5.1 文档和源码分析

先阅读 README、Python DUT 接口、RTL 源码和指导文档，建立功能点与检测点文档。随后进行静态源码审查，重点审查组合预测逻辑、依赖判断表达式、rs1=xn 状态机、复位和位宽处理。

### 5.2 测试环境建设

实现 `create_dut`、`dut` fixture、env 封装和基础 API。时序测试统一通过 Step 推进，API 负责设置输入、推进周期、读取输出，避免测试用例直接散落操作底层信号。

### 5.3 功能覆盖模型

按功能分组建立覆盖点：API 基础能力、预测类型、JALR rs1 类型、依赖等待场景、寄存器读取状态、复位/无效输入和边界立即数。每个测试用例通过功能覆盖标记与功能点、检测点关联。

### 5.4 定向测试

编写定向测试覆盖以下场景：

- JAL 基本 taken 与 PC/imm 操作数。
- Bxx 负偏移 taken、正/零偏移 not taken。
- JALR rs1=x0、x1、xn 三类目标操作数。
- rs1=x1 在 OITF 非空、IR 冲突、依赖解除条件下的等待行为。
- rs1=xn 在 OITF/IR 相关、IR 清除、IR 不使用 rs1、读请求保持/清除条件下的行为。
- `dec_i_valid=0`、复位期间和复位释放后的边界行为。

### 5.5 随机测试

在定向测试完成后，对 pc、立即数、rs1 编号、依赖信号组合进行可重复随机测试。随机测试应使用固定种子和 `ucagent.repeat_count()`，通过 Python 参考计算函数生成期望输出。

### 5.6 Bug 记录与闭环

若发现 DUT 行为与规格不一致，保留触发问题的 Fail 测试用例，并在 bug 分析文档中记录功能标签、测试用例、复现条件、源码定位、问题原因和修复建议。静态分析发现的潜在 Bug 必须通过动态测试验证或标记为误报，不能残留待验证占位。

## 6. 完成标准

完成标准如下：

- 功能点与检测点文档覆盖 README 中描述的所有预测、等待、读请求、复位和边界行为。
- DUT wrapper、env、API 能稳定创建和驱动时序 DUT。
- 定向测试和随机测试覆盖所有核心功能点，正常功能通过，确认的 DUT Bug 保持 Fail 并完成文档记录。
- 静态 Bug 分析与动态验证完成闭环。
- 测试总结文档说明验证覆盖情况、发现的问题、残余风险和后续建议。
