# e203_exu_alu 验证总结

## 1. 项目概述

- **DUT 名称**: `e203_exu_alu`
- **测试日期**: 2026-05-28
- **测试环境**: UCAgent + pytest + toffee
- **验证方法**: 顶层端口可观测行为验证、功能覆盖驱动、静态分析与动态验证结合
- **验证对象范围**: ALU、BJP、CSR、AGU/LSU、WBCK/COMMIT、异常/flush、MULDIV、NICE

本次验证围绕顶层接口建立了完整的分层验证资产：10 个功能组（FG）、34 个功能点（FC）、102 个检测点（CK），并完成对应测试模板与正式测试实现。验证过程中额外补充了 2 个随机测试函数，用于增强 ALU 与条件分支路径的随机激励覆盖。整体流程覆盖了正常功能、边界条件、异常路径、长流水分类、背压握手和可选扩展接口行为。

## 3. 缺陷结论

### 3.1 缺陷统计

- 动态缺陷文档共记录 14 条 bug 标记条目。
- 对应 9 个唯一 `BG-*` 标签。
- 其中 1 个为置信度 0 的检查点定义问题，其余为设计缺陷或高风险实现问题。

### 3.2 主要缺陷分布

1. **AGU / 异常路由缺陷**
   - `BG-AGU-MISALIGN-ROUTE-98`
   - `BG-AGU-LOAD-RSP-DROP-97`
   - 主要表现为 AGU 错位异常被并入 IFU 异常路径、对齐 load 的响应数据与 buserr 未正确传播。

2. **执行期异常归因缺陷**
   - `BG-EXEC-MISALIGN-ROUTE-98`
   - `BG-EXEC-BUSERR-ROUTE-97`
   - 主要表现为执行期访存异常被错误映射到 IFU 字段，导致 `cmt_o_misalgn` / `cmt_o_buserr` 失真。

3. **MULDIV 长流水分类缺陷**
   - `BG-MDV-BUSY-NOLONGPIPE-88`
   - `BG-MDV-LONGPIPE-MISS-90`
   - 主要表现为 MULDIV 发射与 busy hold 场景下 `i_longpipe` 未正确反映多周期属性。

4. **NICE 多周期 itag 写回缺陷**
   - `BG-NICE-ITAG-WBCK-MISS-76`
   - 主要表现为 `nice_longp_wbck_valid` 在多周期返回场景下未正确拉高。

5. **CSR 非法访问提交属性缺陷**
   - `BG-CSR-ILEGL-IFU-MAP-96`
   - 主要表现为 `csr_access_ilgl` 被错误并入 `cmt_o_ifu_ilegl`，污染 IFU 非法取指异常归因。

6. **检查点定义问题**
   - `BG-ALU-CMP-EQNE-0`
   - 该项不是 RTL 功能缺陷，而是 `CK-CMP-EQ-NE` 将 EQ/NE 写回语义错误分配给常规 ALU，应迁移到 BJP 条件分支语义验证。

### 3.3 静态分析闭环情况

- `BG-STATIC-001-MISALIGN-ROUTE` 已关联 `BG-AGU-MISALIGN-ROUTE-98`
- `BG-STATIC-002-CSR-ILEGL-MAP` 已关联 `BG-CSR-ILEGL-IFU-MAP-96`

静态分析提出的 2 个高置信度问题均已被动态验证证实，不存在遗留的未决静态占位项。

## 4. 测试质量评估

### 4.1 有效性

- 定向测试能够稳定复现 AGU、异常路径、MULDIV 和 NICE 相关缺陷，缺陷检出能力较强。
- 随机测试能够在无参考模型前提下，为 ALU 与 BJP 路径提供额外组合激励覆盖。
- 测试整体遵循“Fail 优先归因设计缺陷”的原则，避免为掩盖问题而弱化断言。

### 4.2 局限性

- 当前未启用参考模型，因此随机测试主要集中在可直接由 Python 算法推导期望值的功能点。
- NICE、MULDIV 和 AGU 某些更复杂时序场景仍以定向用例为主，随机覆盖深度有限。
- 线覆盖率提升阶段被任务流程跳过，当前总结不对具体 line coverage 数值作结论。

### 4.3 断言合理性回顾

- 功能正确性类断言均基于端口输出语义，不依赖内部信号。
- 已确认的设计缺陷均由 Fail 用例承载并在 `bug_analysis.md` 中建立追踪。
- 对 `BG-ALU-CMP-EQNE-0` 已明确标记为检查点定义问题，而非继续误判为 RTL bug。

## 5. 经验与改进建议

### 5.1 设计侧建议

1. 将 IFU 异常与执行期异常、CSR 异常的归因彻底解耦，避免简单地将输入侧异常直接并入 IFU 字段。
2. 重新审视 AGU 对对齐 load/store 的提交与写回时序，不应在请求拍抢先完成提交而忽略响应拍信息。
3. 为 MULDIV 与 NICE 多周期路径建立更明确的长流水/itag 握手约束，减少顶层对“子模块一定会正确给出 longpipe”的隐式依赖。

### 5.2 验证侧建议

1. 若后续引入参考模型，优先补强 CSR、AGU 地址生成和 MULDIV/NICE 时序协同的随机测试。
2. 对 `CK-CMP-EQ-NE` 做文档重构，避免检查点定义与 ISA/RTL 语义不一致。
3. 可在后续版本增加更系统的 flush 与背压交叉随机测试，重点覆盖长流水中断、响应延迟与提交阻塞组合场景。

### 5.3 流程侧建议

1. 静态分析结论应尽早反哺检查点定义，避免出现“静态认为是 bug，但测试仍按错误行为写通过断言”的偏差。
2. 对可选宏接口（如 NICE / CSR_NICE）应在覆盖模型中统一使用 `hasattr` 守卫，减少构建变体带来的误报。

## 6. 最终结论

`e203_exu_alu` 的验证目标已基本完成，功能分解、覆盖模型、定向测试、静态缺陷验证、随机测试和总结文档均已交付。当前结论是：该 DUT 的常规 ALU/BJP/CSR 基础路径大体可驱动、可观测，但在异常归因、AGU 响应提交、MULDIV 长流水分类、NICE itag 写回等关键控制路径上存在多处明确设计缺陷，尚不具备“无风险集成”条件。

若以可用性排序，优先修复顺序建议如下：

1. AGU/执行期异常路由与 load 响应丢失问题
2. CSR 非法访问异常归因问题
3. MULDIV 长流水分类问题
4. NICE 多周期 itag 写回问题
5. 检查点定义文档与覆盖模型的一致性问题

在上述高优先级问题修复前，不建议将当前 `e203_exu_alu` 视为功能完全正确的执行单元实现。
